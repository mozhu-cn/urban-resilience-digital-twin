# Urban Resilience Digital Twin — Miyazaki City

A physics-guided digital twin framework for **urban infrastructure resilience
assessment under extreme flooding**, integrating:

1. **Terrain-informed cellular-automata flood simulation** — 650×650
   (422,500-cell) high-resolution hazard evolution with heterogeneous
   drainage and subsurface storage saturation (Numba JIT accelerated);
2. **Interdependent power–communication network modeling** — network-based
   dependency mapping and **time-delayed cascading failures** driven by
   backup-battery depletion;
3. **Adaptive restoration optimization** — flood-constrained dynamic road
   networks, multi-objective repair prioritization, and Dijkstra-based fleet
   routing;
4. **Interactive 4D visualization** — Plotly animation of the full
   disaster–response–recovery cycle.

The framework is evaluated on a case study of **Miyazaki City, Japan**, under
an extreme typhoon rainfall scenario (peak 100 mm/h, 8 h).

## Repository layout

```
├── DigitalTwin/            # Final, modular simulation package
│   ├── config.py           # All tunable parameters
│   ├── main.py             # Simulation driver (run_simulation)
│   ├── data/               # OSM + elevation data loading, terrain grid
│   ├── flood_model/        # CA flood engine + drainage model
│   ├── infrastructure/     # Power/communication deployment + dependencies
│   ├── failure_model/      # Flood damage + battery depletion (cascades)

│   └── experiments/        # Baselines, sensitivity analysis, figures
├── paper/                  # Submission manuscript (LaTeX + references)
├── results/                # Experiment outputs (CSV + figures)
├── legacy/                 # Historical development scripts (archived)
├── tools/                  # Auxiliary scripts (docx extraction, DOI lookup)
└── run.py                  # Convenient entry point
```

## Quick start

```bash
# 1. Install dependencies
pip install -r DigitalTwin/requirements.txt

# 2. Run the full simulation (interactive 4D animation)
python run.py

# 3. Headless run with custom settings
python run.py --grid-size 200 --num-frames 12 --no-animation

# 4. Reproduce the paper experiments (baselines + sensitivity + figures)
python run.py --experiments
```

> **Note on data:** the first run downloads the OSM road network and
> elevation data from the web (OpenStreetMap + Open-Meteo) and caches them in
> `DigitalTwin/miyazaki_ultimate_cache.pkl`. Subsequent runs use the cache.
> A pre-populated cache is included in this repository, so the experiments
> run offline.

## Reproducing the paper

| Output | Command | Result |
|---|---|---|
| Main scenario | `python run.py` | `simulation_history.csv` |
| Baselines (static flood, no restoration) | `python -m DigitalTwin.experiments.run_baselines` | `results/baselines_*.csv` |
| Sensitivity analysis | `python -m DigitalTwin.experiments.sensitivity` | `results/sensitivity_*.csv` |
| All figures | `python -m DigitalTwin.experiments.make_figures` | `results/fig*.png` |

The paper manuscript lives in `paper/manuscript.tex` (compile with
`pdflatex` + `bibtex`); figures are generated by the experiments and copied
to `paper/figures/`.

## Key model parameters (DigitalTwin/config.py)

| Parameter | Value | Meaning |
|---|---|---|
| `grid_size` | 650 | grid cells per side (422,500 cells) |
| `dt_ca_seconds` | 10 | CA sub-step (s) |
| `total_hours` / `num_frames` | 8 / 24 | event length and output frames |
| `rain_peak_mmh` | 100 | peak rainfall (mm/h) |
| `substation_flood_threshold` | 0.5 m | flood depth that fails a substation |
| `road_block_threshold` | 0.3 m | flood depth that blocks a road |
| `num_power` / `num_comm` | 15 / 40 | substations / base stations |
| `battery_min_h`–`battery_max_h` | 3–5 h | backup battery duration |
| `num_fleets` | 2 | repair fleets |
| `seed` | 42 | reproducibility seed |

## Development history

The `legacy/` directory archives the iterative development scripts
(`dynamic_flood_simulator.py` → `miyazaki_master_simulator.py` → `AAAA.py`
→ `ca_flood_twin.py` → `ultimate_ca_flood_twin.py` →
`final_resilience_twin.py` → `alllast.py`) that were consolidated into the
modular `DigitalTwin/` package.
